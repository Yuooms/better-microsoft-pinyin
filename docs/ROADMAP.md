# 路线图

## 当前状态（v0.2.0，已发布）

已实现：

- **两级云候选**：云联想（严格按音节数）默认开启；扩展云联想（输入是前缀的更长词）默认关闭，打开后各自有开关、采纳键与条数；本地已有的词自动让位。
- **云词源可切换**：严格槽可在 Bing（默认）与搜狗之间切换，扩展槽固定 Bing；搜狗取不到时严格槽回退 Bing，扩展关闭时不访问 Bing。
- **主链路**：按键重建拼音 → 防抖 → 读候选窗判断输入状态 → Bing 查询 → 清洗 → 读音分区 → 浮窗展示 → 按键上屏。
- **内置读音词库**：15 万词 + 4.4 万单字读音，候选驱动 DP 校验读音；简拼（`ystl`）先展开成全拼再查云端。
- **键位**：采纳键点一下再按键即可设置（`·` 是默认值）；扩展键是一个列表，可增删、拖动排序，键位分配支持「自动接在本地候选之后」与「手动指定」。自动模式下列表压暗禁用，手动模式下「显示条数」跟着键数走。
- **英文模式**：可选；采纳前用 UIA ValuePattern 校验文本尾部，校验不通过就放弃。
- **候选窗读取**：按坐标命中候选条，读候选词与矩形，用于去重、键位分配与定位。
- **网络自适应**：多端点，真实查询体检，失败自动切换。
- **词库可视化**：自定义短语可增删改、导入导出、批量删除，采纳云词后自动写入并补一条简拼；自学习词只读展示、可导出、可删除、删除前自动备份且能回退。
- **输入统计（默认关闭）**：按天 / 按小时 / 按程序累计输入量，柱状图与程序排行；纯本地，可开关、可清空。
- **外观**：设置窗口基于 WPF-UI（FluentWindow + TitleBar + NavigationView）；支持浅色 / 深色 / 跟随系统、Windows 11 22H2 以上的 Mica 窗口材质（可关）与自定义背景图（带透明度）。候选浮窗仍用自研材质，Win10 走 `SetWindowCompositionAttribute`。
- **设置框架**：模块化导航，云联想页 + 词库页 + 输入统计页 + 常规页 + 外观页 + 网络与环境页 + 关于页。常规页提供开机启动开关（HKCU Run，可自愈路径），以及可选的「以管理员身份启动」（登录计划任务，`RunLevel=HighestAvailable`）。
- **检查更新**：「关于」页读 GitHub 的 `releases/latest`，发现正式版只提示、不自动下载；用户手动「下载更新」到本机缓存（显示路径与大小，可打开/清理），再手动「安装并重启」。启动时每天最多查一次，可关闭。
- **发布**：GitHub Release 提供自包含 zip（自带 .NET 运行时），解压即用。

未实现但有明确前置条件的：

- UIA 事件通道（当前依赖系统插入符定位，Chromium 类窗口会退化到鼠标位置）。
- 原生候选槽位注入。
- 查询缓存：`AppSettings.CacheMinutes` 只是预留字段，链路里还没有接缓存层。

## 优先级一：UIA 事件通道

**为什么需要**：现在靠 `GetGUIThreadInfo` 拿插入符。原生编辑控件没问题，但 Chromium / Electron / WPF / UWP 这类自绘文本控件没有系统插入符，浮窗会退回鼠标位置，体验明显变差。

**要做的**：

1. 把 `UiaWorker` 从阻塞队列循环改成 `MsgWaitForMultipleObjects` + `GetMessage` 的混合消息泵（UIA 事件回调投递到注册订阅的那条线程，没有消息泵就永远收不到）。
2. 常开订阅 `UIA_MenuOpenedEventId`(20003) / `MenuClosed`(20007)；组字期间加开 `AddStructureChangedEventHandler`(20002)。
3. 事件回调铁律：只读缓存属性、全 try/catch、`runtimeId` 声明为 `IntPtr` 且永不触碰。
4. 用 `IUIAutomationCacheRequest` 一次性带回 Name/矩形/IsOffscreen，把每次读取的跨进程往返从 N 次降到 1 次。
5. 补充锚点来源：`TextPattern2::GetCaretRange` 覆盖 Chromium 类窗口。

**验收**：在 Chrome 地址栏与 VS Code 编辑器里输入，浮窗能贴在光标下方而不是鼠标位置。

## 优先级二：原生候选槽位注入（长期）

**目标**：把云词直接写进微软拼音自己的候选列表（视觉上的第 2 位），由输入法原生流程完成选词、上屏与自学习。

**为什么现在不做**：需要挂钩输入法进程内部函数并按其版本适配偏移量，工程量大、随系统更新失效、且必然触发安全软件关注。当前架构已经把这条路留好了接口（见下），但不建议作为主线。

**前置条件**（按依赖顺序）：

1. **符号与偏移**：能按本机组件版本取得所需函数的地址与结构体字段偏移；拿不到就必须整体放弃，不能盲打补丁。
2. **占位机制**：输入法重新生成候选列表时插入一个"云候选占位"，结果到达后填充；等待期间不预留空位，避免本地候选编号跳动。
3. **去重与回填**：占位前先比对本地候选；结果为空或全部重复时不显示，且不能留下空占位。
4. **缓存与超时**：输入法侧的请求配额与等待上限要接管，否则会出现"发出请求却不接纳结果"。
5. **失败即回滚**：任何一个必需挂钩缺失就整体不安装，保证输入法行为与未安装时完全一致。
6. **版本矩阵**：至少覆盖 Windows 10 22H2 与 Windows 11 各主流版本，并在每次系统更新后回归。

**接入方式（已预留）**：

- 实现 `IInputIntegration`，`Capabilities.CanInjectNativeCandidate = true`。
- `TryInjectNativeAsync` 负责写入候选槽位，`TryCommitAsync` 返回 `NotSupported`（上屏由输入法完成）。
- `CloudAssistController` 只按能力分支，届时无需改动；`Core` 一行不改。
- 跨进程通信走 `BetterPinyin.Contracts` 里已定义的消息与 `ITransport`，把 `InProcessTransport` 换成命名管道/共享内存实现即可，消息格式不变。

**验收**：云词出现在输入法候选列表第 2 位；不选它时本地候选编号不跳动；无结果时候选完全不变；卸载后输入法行为与安装前一致。

## 其他候选功能

按用户价值排序：

| 功能 | 状态 | 说明 |
|---|---|---|
| 云词收藏 | 已实现 | 采纳过的云词写进用户词库（`words.json`），并同步到自定义短语，下次直接本地命中 |
| 快捷短语 | 已实现 | 词库页可直接编辑自定义短语，输入码触发长文本；简拼记录会自动补写 |
| 界面主题 | 已实现 | 跟随系统 / 浅色 / 深色，Win11 22H2+ 的 Mica 窗口材质，外加自定义背景图与透明度 |
| 云联想来源切换 | 已实现 | 严格槽可选 Bing / 搜狗；扩展槽固定 Bing；关闭扩展开关后不再访问 Bing |
| 查询缓存 | 未实现 | `AppSettings.CacheMinutes` 只是预留字段，网络页标注为「未启用」，链路里还没有缓存层 |
| 多源交叉验证 | 未实现 | 两个来源都给出同一词时才显示，进一步降噪；`CloudProviderAnswer` 已能按次拿到来源，合并即可 |

## 已实测不可用的云词源（2026-11-16）

逐个发过真实请求，不是查文档：

| 来源 | 结果 |
|---|---|
| 百度 `olime.baidu.com/py` | 恒返回 `errno 19`，主页 404；加 Cookie / Referer / 改 POST 都一样 |
| 腾讯 `ime.qq.com/fcgi-bin/getword` | DNS 解析失败（os error 11004） |
| 讯飞 `ime.iflytek.com` / `pinyin.iflytek.com` | 域名无响应，只有语音与大模型开放平台，没有拼音接口 |
| 谷歌 Input Tools | 国内直连与代理均超时（境外网络可用，但本机不可达） |

搜狗可用但走私有二进制协议，细节见 [TECH-NOTES 第二十四节](TECH-NOTES.md)。将来这些源复活时，按 [FEATURE-GUIDE](FEATURE-GUIDE.md) 的「再加一个云词源」接入即可，不用改控制器。

## 已知技术债

- `NetworkEnvironment` / `EndpointSelector` 尚未独立成类：当前由客户端"按端点顺序尝试"承担自动切换，够用但不够精细（没有冷却期与连续失败计数）。
- 扩展槽按 Bing 原序展示，没有按"多余音节数"或置信度重排。
- 词库不含近年新词，简拼对这类专名无能为力（读音校验不受影响）。
- 设置页未做输入校验的即时反馈（超范围会静默夹到合法区间）。
- 没有安装包：只有绿色版 zip，没有安装器、快捷方式与卸载项；自动更新也建立在"整个目录可写"这个前提上。
- 更新检查只认 GitHub 的公开发布接口，镜像站或完全断网的网络环境用不了；下载速度取决于直连质量。
