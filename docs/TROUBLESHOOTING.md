# 排障指南

先看日志：`%LOCALAPPDATA%\BetterPinyin\logs\app.log`。里面会记录每次云联想的处理结果，例如：

```
19:37:52  [云联想] yisitalu → 伊斯塔露（来源 bing-osjson，锚点 候选窗）
19:38:10  [云联想] ystl：云端无可用候选（原始 12 条均被过滤）
19:38:25  [云联想] weiruan：5 条候选均已在本地区命中或读音不符
```

日志里没有输入内容本身以外的信息，可以放心贴到 issue 里。

## 症状 → 原因 → 处理

### 完全没反应，浮窗从不出现

1. 确认程序在托盘里运行。
2. 打开「设置 → 网络与环境」，看环境自检：
   - **微软拼音：未检测到** → 本功能只支持微软拼音。
   - **双拼：已开启** → 双拼下按键串不是全拼，功能会保持停用（这是设计如此）。
3. 看「设置 → 云联想 → 运行诊断」是否有记录：
   - 有记录但都是"云端无可用候选" → 网络或端点问题，去网络页做一次端点体检。
   - 完全没有记录 → 键盘钩子没收到按键。检查是否被安全软件拦截，或目标程序以管理员身份运行。

### 浮窗出现了，但按采纳键没上屏

- 目标程序是**管理员权限**运行时，普通权限程序无法向它发送输入（系统限制）。需要以管理员身份运行本程序。
- 日志里若出现 `上屏中止：组字未被取消`，说明 Esc 没能取消组字，此时程序会主动放弃上屏以避免"拼音与中文混杂"。

### 浮窗位置偏移

- 候选窗矩形来自 UI Automation，插入符来自系统 API，两者都是物理像素。浮窗按**所在显示器的工作区**定位，混合 DPI 多屏也已支持；若仍偏移，请附上截图与显示器排列。
- 没有系统插入符的程序（Chromium、Electron 自绘文本）会退回鼠标位置定位，浮窗可能不在光标正下方。

### 云候选总是不出现

按顺序排查：

1. **是不是本来就有？** 云词与微软拼音当前候选重复时会主动隐藏（避免"云联想没带来新信息"）。日志会写"均已在本地区命中或读音不符"。
2. **是不是读音对不上？** 例如输入 `yisital` 时，云端给出「艾石头al87」这类混排词会被过滤。这是预期行为。
3. **是不是纯缩写？** `ystl` 这类直查返回的多是拉丁垃圾，会被整体过滤。全拼（`yisitalu`）与未打完的全拼（`yisital`）命中率明显更高。
4. **网络是否可用？** 网络页点「重新检测」，看是否有任一端点可用。

### 只有扩展云联想，没有「云联想」那一条

严格槽为空有两种正常原因，日志会写清楚：

- `严格=无（已在本地候选）`：你要的词本地已经能选到，按设计不重复展示。
- `严格=无（云端无整词匹配）`：Bing 的联想里没有字数相等的那一条。例如 `lianxiang` 只返回「联想电脑管家 / 联想官网」，没有单独的「联想」。这不是 bug。

### 按数字键没反应，或者选走了本地候选

- 数字键只在浮窗可见、且该编号**大于本地候选数**时才绑定。本地显示 5 个 → 只有 6/7/8 归本程序。
- 本地候选有 9 个时数字键已经用完，扩展条目不显示数字（日志会提示）。
- 按下瞬间本地候选数变了，程序会放弃提交并把按键**注入回去**，日志写「回填：本地候选数变为 N」。

### 英文模式下按采纳键没有上屏

英文模式默认关闭，且采纳前有一道文本校验：

- 需要「设置 → 云联想 → 英文状态下也联想」打开。
- 只有焦点控件支持 UIA ValuePattern 时才能确认文本尾部，读不到就会放弃，日志写 `放弃：无法确认已输入内容`。
- 不放心的话把「英文模式采纳」改成「仅提示，不上屏」。

### 设置窗口没有毛玻璃效果

- 设置窗口用 WPF-UI 的 `FluentWindow`，当前固定 `WindowBackdropType=None`。
- **Windows 10 不支持 Mica / 亚克力**，所以统一是纯色底；想要观感去「外观 → 使用自定义背景图」选一张图并调低透明度。
- Windows 11 想启用 Mica，把 `SettingsWindow.xaml` 的 `WindowBackdropType` 改成 `Mica` 即可（需要 22621+）。
- 候选浮窗的「亚克力」是另一套实现（`Backdrop.cs`），与设置窗口无关。

### 拖动设置窗口很卡

- 确认没有手动把 `WindowBackdropType` 改成 `Mica` / `Acrylic`；Windows 10 上那两个值不会生效，只会和背景画刷抢绘制。
- 使用自定义背景图时，图片会被缩放铺满窗口；极大图片（4K 以上）首次加载可能慢一瞬，换成 1080p 左右即可。

### 深色主题下有文字看不清

这类问题几乎都是"某个颜色没走动态资源"：

- 代码里直接 `new SolidColorBrush(...)` 或 `Application.Current.Resources["..."]` 取到的画刷不会随主题更新，应改用 `SetResourceReference` 或 `ThemeManager.ResolveBrush`。
- 启动日志里查「主题资源自检通过」；如果出现「主题资源缺失」，说明有键名拼错，`DynamicResource` 会静默保留原值。

### 端点体检全部失败

- 检查是否需要代理。程序默认跟随系统代理，可在设置里改为自定义。
- 部分企业网络会拦截搜索建议接口，此时功能进入静默待机，不影响输入法本身。

### 程序启动后没有任何窗口

- 默认只在托盘中常驻，双击托盘图标打开设置。首次运行（尚无配置文件）会自动打开设置窗口。
- 若托盘图标也不见了，看日志里是否有 `OnStartup` 错误记录；程序会把启动异常写进日志并弹窗提示。

### 同步到微软拼音后没有排在第 2 位

**这是输入法的限制，不是本程序的 bug。** 实测（Windows 10 19045，逐条读原生候选窗验证）：

- 写入 `ChsPinyinEUDPv1.lex` 后**不需要重启输入法**，几秒内自动生效，短语会出现在原生候选里；
- 输入法**不会回写覆盖**该文件，外部写入能稳定保留；
- 但记录中的「位置」字段虽然被正常保存，输入法**不按它排序**——所有自定义短语一律排在候选第 1 位，
  填 2~9 与填 1 效果相同。把两条同拼音短语按位置 5、2 写入，显示顺序仍是文件顺序。

所以「让云词出现在原生候选第 N 位」在当前版本的微软拼音上做不到。本程序的做法是：
采纳后自动写进自定义短语，保证它**出现在原生候选里**（排第 1），并在词库页如实标注位置不起作用。

### 打字变卡

本程序的键盘钩子回调只做过滤与转交，不做任何 I/O。若确实感到卡顿：

1. 关闭云联想开关，确认是否由本程序引起。
2. 检查是否有其它程序也在装低级键盘钩子（多个钩子会串行执行）。
3. 把日志与复现步骤一并提交。

## 提交问题时请附上

1. `%LOCALAPPDATA%\BetterPinyin\logs\app.log` 的相关片段。
2. 「设置 → 网络与环境」页的自检结果截图。
3. Windows 版本（`winver` 里的版本号）。
4. 出问题的程序名称（记事本 / VS Code / Chrome / 微信 / 某个游戏…）。
