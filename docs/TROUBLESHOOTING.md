# 排障指南

先看日志：`%LOCALAPPDATA%\BetterPinyin\logs\app.log`。里面会记录每次云联想的处理结果，例如：

```
19:37:52  [云联想] yisitalu → 伊斯塔露（来源 bing-qsonhs，锚点 候选窗）
19:38:10  [云联想] ystl：云端无可用候选（原始 12 条均被过滤）
19:38:25  [云联想] weiruan：5 条候选均已在本地区命中或读音不符
```

日志里没有输入内容本身以外的信息，可以放心贴到 issue 里。

## 症状 → 原因 → 处理

### 完全没反应，浮窗从不出现

1. 确认程序在托盘里运行。
2. 打开「设置 → 网络与环境」，看环境自检：
   - **微软拼音：未检测到** → 本功能只支持微软拼音。
   - **双拼：已开启** → 双拼下按键串不是全拼，功能会保持停用（这是设计如此）。
3. 看「设置 → 云联想 → 运行诊断」是否有记录：
   - 有记录但都是"云端无可用候选" → 网络或端点问题，去网络页做一次端点体检。
   - 完全没有记录 → 键盘钩子没收到按键。先看下一节（目标程序是不是管理员权限），再排查安全软件拦截。

### 只在某个程序里不生效（管理员权限的程序）

现象：别的地方都正常，惟独某个程序里浮窗从不出现，而且「运行诊断」里**一条记录都没有**——不是"没有候选"，是根本没识别到输入。

原因：那个程序以**管理员权限**运行。Windows 的 UIPI 规定，低完整性进程的低级键盘钩子收不到高完整性窗口的按键；钩子不会报错，只是永远不被调用。同理，向那个窗口注入上屏文本也会被拒。常见的有 WorkBuddy、任务管理器、注册表编辑器，以及从管理员终端启动的编辑器。

确认：任务管理器 →「详细信息」→ 右键列标题 →「选择列」→ 勾选「以管理员身份运行」，看该程序是不是"是"。

处理：

- 「设置 → 云联想」顶部会出现提示块，点**以管理员身份重启**。提权后可以辅助所有管理员程序。
- 不想让本程序提权，就把那个程序改成普通权限启动——多数程序本身并不需要管理员，只是被从管理员终端或管理员快捷方式拉起来的。
- 开机自启仍是普通权限；要开机即提权，需要把启动项换成"以最高权限运行"的计划任务。

日志里对应的一行是 `[云联想] WorkBuddy 以更高权限运行（读不到具体级别）……`：读不到级别本身就是判据——普通权限进程去读管理员进程的令牌会被直接拒绝。

### 浮窗出现了，但按采纳键没上屏

- 目标程序是**管理员权限**运行时，普通权限程序无法向它发送输入（系统限制）。需要以管理员身份运行本程序。
- 日志里若出现 `上屏中止：组字未被取消`，说明 Esc 没能取消组字，此时程序会主动放弃上屏以避免"拼音与中文混杂"。

### 浮窗位置偏移

- 候选窗矩形来自 UI Automation，插入符来自系统 API，两者都是物理像素。浮窗按**所在显示器的工作区**定位，混合 DPI 多屏也已支持；若仍偏移，请附上截图与显示器排列。
- 没有系统插入符的程序（Chromium、Electron 自绘文本）会退回鼠标位置定位，浮窗可能不在光标正下方。

### 云候选总是不出现

按顺序排查：

1. **是不是本来就有？** 云词与微软拼音当前候选重复时会主动隐藏（避免"云联想没带来新信息"）。日志会写"均已在本地区命中或读音不符"。
2. **是不是读音对不上？** 例如输入 `yisital` 时，云端给出「艾石头al87」这类混排词会被过滤。这是预期行为。
3. **是不是纯缩写？** `ystl` 这类直查返回的多是拉丁垃圾，会被整体过滤。全拼（`yisitalu`）与未打完的全拼（`yisital`）命中率明显更高。
4. **网络是否可用？** 网络页点「重新检测」，看是否有任一来源可用（Bing 端点与搜狗分开列出）。
5. **钩子有没有收到键？** 用环境变量 `BETTERPINYIN_TRACE_KEYS=1` 启动程序，日志里会逐键打印
   `trace 键 vk=… own=… mod=…` 与 `trace 组字 "…"`。看到键但看不到组字，说明按键被当成快捷键或自身注入；
   两者都看不到，说明钩子没装上（通常是被安全软件拦了）。

### 在 QQ / 微信 / 浏览器里不联想

这些程序用的是自绘文本控件（Chromium / Electron），没有系统插入符，程序只能退回鼠标位置
去找候选窗。以前鼠标离输入框远一点就会找不到候选条，日志写「当前不是可联想的输入状态」；
现在会再在前台窗口范围内补一次网格搜索，正常情况下不再受鼠标位置影响。

如果仍然不联想：

1. 确认微软拼音是中文状态（英文状态下字母直接上屏，本程序不接管）；
2. 看「运行诊断」页有没有「当前不是可联想的输入状态」，以及同一时间日志里有没有 `锚点 候选窗` 的成功记录；
3. 用 `dotnet run --project tools/ImeProbe -- --focus=QQ --caret` 看锚点来源，
   详见 [技术笔记第二十三节](TECH-NOTES.md)。

### 切到搜狗后没有云联想

1. 看「运行诊断」页：来源那一行会写 `严格=sogou，扩展=…`。如果连这一行都没有，说明查询根本没发出去（先按上一节排查）。
2. 搜狗只返回「整串拼音」的整词候选，且条数少（实测 1~3 条）。输入太短（如 `nh`）或不是全拼时基本没有结果，属正常。
3. 搜狗接口没有公开契约，可能被限流或改协议。切回 Bing 验证一下：Bing 有候选、搜狗没有，就是接口侧的问题。
4. 扩展云联想固定用 Bing；如果扩展开关关掉了，程序不会再访问 Bing——所以「严格没有、扩展也没有」时，检查一下来源是不是停在搜狗。

### 只有扩展云联想，没有「云联想」那一条

严格槽为空有两种正常原因，日志会写清楚：

- `严格=无（已在本地候选）`：你要的词本地已经能选到，按设计不重复展示。
- `严格=无（云端无整词匹配）`：所选来源的联想里没有字数相等的那一条。例如 `lianxiang` 只返回「联想电脑管家 / 联想官网」，没有单独的「联想」。这不是 bug。
- 选了搜狗时，严格槽取不到会用 Bing 的结果顶上（日志的来源会写 `严格=bing-…`）；只有扩展云联想关闭、Bing 压根没请求时才没有这条回退。

### 按数字键没反应，或者选走了本地候选

- 数字键只在浮窗可见、且该编号**大于本地候选数**时才绑定。本地显示 5 个 → 只有 6/7/8 归本程序。
- 本地候选有 9 个时数字键已经用完，扩展条目不显示数字（日志会提示）。
- 按下瞬间本地候选数变了，程序会放弃提交并把按键**注入回去**，日志写「回填：本地候选数变为 N」。

### 英文模式下按采纳键没有上屏

英文模式默认关闭，且采纳前有一道文本校验：

- 需要「设置 → 云联想 → 英文状态下也联想」打开。
- 只有焦点控件支持 UIA ValuePattern 时才能确认文本尾部，读不到就会放弃，日志写 `放弃：无法确认已输入内容`。
- 不放心的话把「英文模式采纳」改成「仅提示，不上屏」。

### 设置窗口没有毛玻璃效果

- 设置窗口用 WPF-UI 的 `FluentWindow`，材质由 `WindowBackdropType` 控制，可以在「外观 → 窗口材质」关掉。
- **Mica 需要 Windows 11 22H2（build 22621）及以上**；Windows 10 与更早的 Windows 11 自动退回纯色底，想要观感去「外观 → 使用自定义背景图」选一张图并调低透明度。
- 材质开着但看不出来：先确认「外观」里开关是开的，再看日志里的 `窗口材质：Mica，系统 <build>`；剩下能影响的通常是窗口没在前台或桌面壁纸本身接近纯色。
- 候选浮窗的「亚克力」是另一套实现（`Backdrop.cs`），与设置窗口无关。

### 拖动设置窗口很卡

- 材质只在 Windows 11 22H2（22621）及以上启用，走 DWM 合成、不做逐帧模糊；Windows 10 上程序根本不会开材质，所以这一项不应该是原因。
- 更常见的是自定义背景图太大（4K 以上）：铺满窗口要重采样，换成 1080p 左右的图即可。
- 其次是 200% 以上的缩放比例下整窗重绘，属于 WPF 本身的限制，关掉背景图能明显缓解。

### 深色主题下有文字看不清

这类问题几乎都是"某个颜色没走动态资源"：

- 代码里直接 `new SolidColorBrush(...)` 或 `Application.Current.Resources["..."]` 取到的画刷不会随主题更新，应改用 `SetResourceReference` 或 `ThemeManager.ResolveBrush`。
- 启动日志里查「主题资源自检通过」；如果出现「主题资源缺失」，说明有键名拼错，`DynamicResource` 会静默保留原值。

### 端点体检全部失败

- 检查是否需要代理。程序默认跟随系统代理，可在设置里改为自定义。
- 体检会分别检测 Bing 的四个端点和搜狗；「当前生效设置」里能看到当前用的是哪个来源。
- 部分企业网络会拦截搜索建议接口，此时功能进入静默待机，不影响输入法本身。

### 程序启动后没有任何窗口

- 默认只在托盘中常驻，双击托盘图标打开设置。首次运行（尚无配置文件）会自动打开设置窗口。
- 若托盘图标也不见了，看日志里是否有 `OnStartup` 错误记录；程序会把启动异常写进日志并弹窗提示。

### 「自学习」和「自定义短语」有什么区别

微软拼音在「设置 → 词库和自学习」里放了两套完全不同的数据，本程序对应两个视图：

| | 自定义短语 | 自学习 |
|---|---|---|
| 来源 | 用户显式添加（本程序采纳云词时自动写） | 输入法根据你的输入习惯自己累积 |
| 文件 | `ChsPinyinEUDPv1.lex` | `ChsPinyinUDL.dat` |
| 效果 | 打对应拼音时**固定**出现在候选里 | 只影响候选的**排序权重**，不保证出现 |
| 可改 | 是，本程序可增删改 | 否，本程序只读 |
| 清空 | 删记录即可 | 输入法设置里的「清除输入历史记录」 |

**为什么自学习只读**：这份文件由输入法高频写入，且输入法在内存里保有副本；外部改写可能被下一次保存覆盖，
格式写坏还会丢掉长期的输入习惯记录。相比之下它只是排序权重，改它的收益远小于风险，所以只做可视化与导出。

拼音一列是**推断值**：文件里只存了「简拼 + 每个字的音节索引（指向输入法私有的 442 音节表）」，
本程序不解码那张表，而是用自己词库的单字读音 + 简拼首字母反推，多音字（重 zhòng/chóng）靠首字母消歧。
生僻字可能推不出来，此时该行为空——不影响查看与导出。

### 打简拼（`ystl`）出不来学过的词

微软拼音的自定义短语**只按「拼音」字段做纯字符串匹配**：写 `yisitalu` 就只有打全拼才出，
它不会自己从全拼推出首字母。所以要让 `ystl` 也能出词，必须再写一条拼音为 `ystl` 的记录。

- 打开「设置 → 词库 → 同时写入简拼」（默认开）。切换开关时会立即为已有短语补写一遍；
- 之后每条短语都会占两条记录：`yisitalu` 与 `ystl`，词库页合并成一行显示（`yisitalu · ystl`）；
- 补写之后要等输入法重载（几秒到十几秒，或切一次输入法），第一次查可能还没生效；
- 若某个简拼已经被别的词占用，本程序不会覆盖它，界面上会提示「简拼 xxx 已被「某词」占用」。

### 扩展云联想的整句没有出现在自定义短语里

**这是默认行为，不是没生效。** 扩展候选多是「伊斯塔路是谁」这类整句，写进短语库会永久占住原生候选的第一位，
而它往往只用一次，所以默认只上屏、不记账（连本程序的用户词库也不记，否则「待同步」会在下次启动被补写回来）。

- 想让扩展词也写进短语：打开「设置 → 词库 → 扩展词也写入短语」；
- 该开关依赖「采纳后自动写入」，总开关关着时它会置灰；
- 严格云联想（按 `·` 采纳的单个词）不受这个开关影响，始终按总开关的设定写入。

### 同步到微软拼音后没有排在第 2 位

**这是输入法的限制，不是本程序的 bug。** 实测（Windows 10 19045，逐条读原生候选窗验证）：

- 写入 `ChsPinyinEUDPv1.lex` 后**不需要重启输入法**，几秒内自动生效，短语会出现在原生候选里；
- 输入法**不会回写覆盖**该文件，外部写入能稳定保留；
- 但记录中的「位置」字段虽然被正常保存，输入法**不按它排序**——所有自定义短语一律排在候选第 1 位，
  填 2~9 与填 1 效果相同。把两条同拼音短语按位置 5、2 写入，显示顺序仍是文件顺序。

所以「让云词出现在原生候选第 N 位」在当前版本的微软拼音上做不到。本程序的做法是：
采纳后自动写进自定义短语，保证它**出现在原生候选里**（排第 1），并在词库页如实标注位置不起作用；
扩展云联想的整句默认不写，原因见上一节。

### 检查更新失败，或者一直提示有新版本

- **连不上 GitHub**：检查走 `api.github.com`，下载走 `objects.githubusercontent.com`。程序跟随系统代理，代理软件只开了 PAC/规则模式时可能命中不了这两个域名，换成全局或直连再试。
- **一直提示有新版本**：多半是版本号没跟上 tag。程序版本取自 `Directory.Build.props` 的 `<Version>`，发布 tag 必须与之一致（例如 `0.1.0` ↔ `v0.1.0`）；tag 里带 `-beta` / `-rc` 的预发布不会被提示。
- **「仓库里还没有正式发布」**：Release 要是已发布的（不是 draft），并且没勾 prerelease。
- 自动检查每天最多一次，手动点「检查更新」不受这个限制。

### 点了「下载更新」没反应，或者下载很慢

- 下载走 `objects.githubusercontent.com`，与检查更新走的 `api.github.com` 不是同一个域名。国内直连经常只有几十 KB/s，70 MB 的包要等很久；可以让代理软件把这两个域名都走代理。
- 下载中进度条会一直走；中断了就是没下完，缓存目录里会留半个 `package.zip`。重下会先清掉同版本的旧目录。
- 下载完成后**不会自动安装**，必须再点「安装并重启」。

### 点了「安装并重启」，但版本没变

1. **安装目录不可写**：放在 `Program Files`、只读盘或被安全软件锁定目录时，程序不会硬替换，会提示手动解压。绿色版请放在用户目录或普通数据盘。
2. **从源码调试启动**：`dotnet run` 时进程是 `dotnet.exe`，自我替换没有意义，程序会明确提示。
3. **看替换日志**：`%LOCALAPPDATA%\BetterPinyin\updates\<tag>\update.log` 里有 robocopy 的退出码。0/1/2/3 表示复制成功，≥8 是失败（常见原因是目标文件还被占用）。
4. 程序在替换期间会退出；如果托盘图标一直没回来，手动运行一次 `BetterMicrosoftPinyin.exe` 即可，安装目录里已经是新版本。
5. 换版本失败后缓存不会被删，可以在「关于」页点「清理」重来。

### 更新缓存占空间

- 位置是 `%LOCALAPPDATA%\BetterPinyin\updates\<tag>`（解压后的目录 + 一个临时 zip）。
- 「关于」页会显示占用大小，可直接「打开文件夹」或「清理」；程序本身不会自动删，因为不知道你还想不想装。

### 打字变卡

本程序的键盘钩子回调只做过滤与转交，不做任何 I/O。若确实感到卡顿：

1. 关闭云联想开关，确认是否由本程序引起。
2. 检查是否有其它程序也在装低级键盘钩子（多个钩子会串行执行）。
3. 把日志与复现步骤一并提交。

## 提交问题时请附上

1. `%LOCALAPPDATA%\BetterPinyin\logs\app.log` 的相关片段。
2. 「设置 → 网络与环境」页的自检结果截图。
3. Windows 版本（`winver` 里的版本号）。
4. 出问题的程序名称（记事本 / VS Code / Chrome / 微信 / 某个游戏…）。
